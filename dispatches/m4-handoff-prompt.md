# Milestone 4 — 脱离作者的交接

你是实施 agent（Grok Build）。调度者 hostor。用户只把关战略。

工作根：`/workspace/openadam-procedure-reuse/`  
先读：`PLAN_BRIEF.md`、`reports/m1-*.md`、`reports/m2-*.md`、`reports/m3-two-layer-reuse.md`，以及三个草稿方法目录。

## 目标（规划）
让**没有参与开发的人或 Agent**，使用已经封装的方法处理新的输入。  
重点检查：安装/理解、调用、结果采用、修复成本。  
少量但相互不同的真实任务即可——发现交接问题，不宣称领域已生产成熟。

## 本轮可交付的「交接包」（诚实边界）
本环境不能假装已装进用户本机 Agent Host（Linux 上 Host preview 曾失败；且用户未授权 import）。因此 M4 的完成定义是：

1. **面向使用者的入口材料**（人 + Agent），不是架构说明书：
   - 这能替我完成什么 / 不做什么
   - 我需要准备什么（规格 + 文件树）
   - 怎样第一次运行（最短命令）
   - 结果怎么读（pass/fail、failedKits/failedIds）
   - 出问题怎么办
2. **冷读者演练脚本**：用「新夹具」（不在原作者开发时用过的那几套）跑上层或下层方法，记录：
   - 是否只靠入口文档就能跑通
   - 卡住点（路径、Node/Go、二进制、规格字段）
   - 手工改了多少
3. **Agent 向入口**：薄 Skill 或等价短说明（若项目已有则审阅并补到「外人可用」）；禁止在 Skill 里写「你必须调用我们的 Procedure」来伪造采用。
4. **交接成本记录表**：另一位使用者要补问几问、改几处路径、有无隐藏依赖。
5. 报告 `reports/m4-handoff.md` + 中文战略摘要。

优先以 `batch-delivery-preflight`（两层）为交接主对象，下层两个方法作为被依赖说明。

## 硬约束
- 不 Host import（除非报告写明仅本地模拟且可逆；默认不做）
- 不 push、不改公开 catalog
- 不把调用次数当成价值证明
- 新夹具要真实不同（新文件/新规格），不是复制 good 改名

## 验收
- 存在 `HANDOFF.md`（或同等）于交接主项目，外人视角可跟
- 至少 2 个新任务夹具跑通或明确记录失败原因与修复
- 交接成本表填写完整
- 战略摘要诚实：能交接什么、还不能（真 Agent 会话选用、本机 Host 安装）

## 明确不做
- 公开市场、自动价值评分平台
- 生成缺失素材
- 扩大 Host 核心

做完停在 M4；可在报告末建议 M5 是否值得开（按真实阻碍），但不要擅自开大范围生成链。
